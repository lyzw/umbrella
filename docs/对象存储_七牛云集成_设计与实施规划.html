成长星球 · 七牛云对象存储集成

分析 · 规划 · 设计（V1.0，待确认后实施）
项目：growth-planet 后端 + growth-planet-admin 前端 日期：2026-09-23 范围：基础设施 + 接入 CMS 菜品图片

一、背景与目标

现状：系统目前没有任何对象存储 / 文件上传能力——无七牛依赖、无上传代码、image.studykid.cn 尚未被引用；图片仅以 URL 文本字段承载（life_dish.image_url、life_family_dish.image_url），且后台前端没有图片录入控件，实际无法设置菜品图。

目标：引入七牛云 Kodo（对象存储），建立统一能力——后端签发上传凭证 + 客户端直传 + 公网 URL 拼接；本期打通「CMS 菜品图片」上传闭环，为后续勋章图标、UGC 图片、Banner 等预留同一套能力。

决策项结论

四、方案设计

4.1 总体架构（客户端直传时序）

运营在「菜品」抽屉选择图片前端 DishesView
请求上传凭证：POST /api/admin/storage/upload-token，body { bizType:"dish", fileName:"cover.png" }前端 → 后端
后端校验并按需签发：校验权限（对象存储:新建）+ bizType/后缀 → 生成唯一 key → 用 AK/SK 签发 uptoken（限定 key、时效、MIME、大小、insertOnly）→ 返回 { token, key, publicUrl, uploadHost, ... }后端 ObjectStorageService
直传七牛：POST {uploadHost}，FormData = token + key + file前端 → 七牛（后端不经手字节）
回填并保存：前端 form.imageUrl = publicUrl → 保存菜品时随表单提交 → 后端落库 image_url前端 → 后端
为什么直传：节省后端带宽与内存、避免大文件经应用层；后端只做「签发凭证 + 校验」，符合最小权限与可审计。

启动校验策略（快速失败 + 优雅降级）

  • 全空（AK/SK/Bucket/Domain 均无）：记 WARN，上传凭证接口返回 E503 存储未配置，不阻断启动（便于 dev/CI 无凭证环境）。
  • 部分配置（有填但不全）：启动失败，防止线上误配导致上传静默失效。
  • 测试环境：application-test.yml 注入 dummy 值，使凭证生成（HMAC 签名，离线可算）可在 IT 中断言。

4.4 Key 生成规则

图片：img/{bizType}/{yyyy}/{MM}/{uuid32}.{ext}     例：img/dish/2026/09/9f3c1a2b...e1.png
视频：video/{bizType}/{yyyy}/{MM}/{uuid32}.{ext}   例：video/dish/2026/09/... .mp4
公网：{imageDomain}/{key}  →  https://image.studykid.cn/img/dish/2026/09/....png
策略：Policy.insertOnly(1) 防覆盖 + mimeLimit + fsizeLimit
  • 后缀白名单：图片 jpg/jpeg/png/webp/gif；视频 mp4/mov/webm（视频本期仅预留能力，不接入业务）。
  • UUID 去连字符，长度 32；按 yyyy/MM 分目录，便于运维与 CDN 命中。

4.5 RBAC 权限点

推荐（决策点 D1）：新增资源 「对象存储」，动作复用「新建」（语义=新建一个存储对象）→ requirePerm(STORAGE, "create")；给 OP 补播。与项目既有扩展方式一致（此前已按需新增 报表导出/核验记录/合规清单 等资源）。

备选：不新增资源，按 bizType 映射到目标资源权限（dish → 菜品库:编辑），零 RBAC 变更但权限隐式。二者择一，见第十一节 D1。

4.6 菜品图片接入（前端 修改）

  • src/api/console.js：新增 getUploadToken(payload)。
  • src/views/DishesView.vue：抽屉新增「菜品图片」表单项 —— el-upload（picture-card、:limit=1、:http-request 自定义、隐藏默认列表），流程：取凭证 → 直传 → 回填 form.imageUrl → 展示缩略图与「移除」；无权限时隐藏。

4.7 部署前置（七牛控制台，非代码）

  1. 创建 Kodo bucket，绑定域名 image.studykid.cn（配置 HTTPS 证书；域名需 ICP 备案）；
  2. 配置 bucket CORS：允许后台站点域名 POST 直传（放行 token、key、file 等表单字段）；
  3. 记录 AK/SK，以环境变量 QINIU_ACCESS_KEY/QINIU_SECRET_KEY 注入部署环境。

六、数据与迁移

  • 无 DDL 变更：image_url 列已存在于 life_dish 与 life_family_dish；DishReq.imageUrl 已落库。
  • 无新增迁移脚本：权限点播种走 AdminDataInitializer 幂等补播（supplementPerm），不新增 SQL，符合「新增资源须同步汇总 schema」之外的既有做法。

七、安全与合规

  • 密钥：AK/SK 仅走环境变量，不写死、不入库、不打印日志；.env.example 仅占位。
  • 最小权限凭证：短时效（默认 1h）+ 限定单一 key + insertOnly + mimeLimit + fsizeLimit，即使凭证泄露影响面可控。
  • 前端直传：文件不经后端，减少带宽与数据面；后端不接收、不落盘用户文件内容。
  • URL 校验：沿用既有 validateDish（仅 http/https、禁 userinfo），防 SSRF/注入式 URL。
