一、拆解说明

1.1 拆解维度

  • 纵向三刀：每个功能点按 DB schema → 后端 API/Service → 前端页面/组件 切分；跨模块公共能力（勋章、额度护栏）单独抽任务。
  • 类型标注：DB（库表/DDL）、后端（接口/逻辑/事务）、前端（页面/组件/状态）、测试（联调/集成/E2E）、配置（权限/通知接入）。
  • 优先级对齐：任务优先级继承自对应 F 的 P0/P1/P2；P0 全部落在 M1。
  • 依赖显式：依赖列引用前置任务编号（T-xxx）或 PRD 既有功能（F-xxx）。

1.2 迭代划分原则

  • M1（Sprint 1 · 核心闭环）：跑通"赚（家务）→花（购物/兑换）→管（看板）→看护（二级监护人）"最小可用闭环；含基础勋章、跨场景额度护栏、安全/隐私/一致性非功能基线。
  • M2（Sprint 2 · 增强补全）：健康打卡、日程提醒、周期任务、预算可视化、流水增强、审核履约、委托时效、手动发放增强，及全量集成测试与 E2E 闭环验证。
