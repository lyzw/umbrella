## 一、改了什么 / 为什么

| 项 | 解决 | 一句话 |
|---|---|---|
| A. 家长按日想吃清单 | R3 | 新增区间查询接口，把"某天某餐的裸引用"升级为"日期×餐次分组的带菜品信息 + 状态 + 采购汇总"视图 |
| B. `status` 流转 | R3 闭环 | 家长可把想吃标记为"已采购 ADOPTED / 已做 COOKED / 回退 MARKED"，带乐观锁 |
| C. 去掉展示路径行锁 | R6 | `daily()` 与 `menuMaintenance()` 是纯读，却对 5 组行加 `FOR UPDATE`；改走只读变体 |
| D. 浏览体验收尾 | 体验 | `DishResp` 补 `categoryName`；菜单页加分类 chips、菜品图、过敏原角标 |
| E. 派生「爱吃/常点」 | 派生 | 从 `usr_child_want_eat` 近期行为加权归纳 Top N，菜单页顶部快捷区 |
| F. `favoriteDishIds` 处置 | 维护 | **保留**（D7-B），不做删除 |

## 三、R3 接口契约（冻结）

```
GET /api/parent/want-eat?childId={id}&from=yyyy-MM-dd&to=yyyy-MM-dd
  权限 PARENT；childId 必填正数；from/to 必填；from<=to；跨度<=31 天（超出 E400）
  鉴权链：positive(childId) → authorization.boundChild(childId) → authorization.requireParent(member.getFamilyId())
  归属派生：familyId 由 member 得到，familyId/sourceType 均不出现在入参
  加锁：无（纯读）
```
- **过期语义**：`menuDate < today` 的行**照常返回**并置 `expired=true`；顶层 `expiredCount` = 过期且 `status=MARKED` 的条数。
  原分析"过期不计入今天"由**默认区间**（前端默认 `from=today`）实现，而非过滤数据。
- **FAMILY 菜品隔离**：按 `(FAMILY, dishId)` 查 `life_family_dish` 时必须带 `family_id = member.getFamilyId()`；查不到 → `missing=true`、`name=null`，**不静默丢行**。
- **无菜单也返回**：想吃行按 `menu_date/meal_type` 分组，`menuId/sourceType` 取自行内 `source_type` 冗余列 + 反查菜单（菜单已删则 `menuId=null`），不因菜单缺失而丢行。

```
POST /api/parent/want-eat/{id}/status
  Body { "status": "MARKED|ADOPTED|COOKED", "expectedVersion": 0 }
  权限 PARENT；须为该行 child 所在家庭的家长；越权/不存在 → 统一越权码，不暴露存在性
  并发：@Version + expectedVersion 不符 → E007_CONFLICT(409)
```

```
GET /api/child/frequent-dish?childId=&limit=6
  CHILD：childId 缺省=本人，传他人 → 403；PARENT：childId 必填且须本家庭
  窗口：近 30 天（含今天）；加权：1/(1+距今天数/7.0)；同权重按最近出现时间倒序
  返回：补全菜品名/图/分类；菜品已删/下架 → 跳过（派生视图允许缺失，与 R3 的"不丢行"原则不同）
```

## 四、影响范围 / 兼容性
- **破坏性变更：无**。3 个新接口 + `DishResp` 增字段（增量）+ 去掉读路径锁（不改契约）。
- 旧接口 `POST /menu/mark-favorite`、`GET /menu/daily`、`GET /child/want-eat` 契约**全部不变**。
- **无数据库迁移**：`status`、`version` 字段已在 P0 建表时就绪（`v005_child_want_eat.sql`）。
- 前端为纯新增页面 + 增量 UI，旧版本小程序不受影响。

## 五、回滚点
- 无迁移、无数据破坏。回滚 = 还原上述文件；已写入的 `ADOPTED/COOKED` 行回滚后仍可被旧逻辑当普通想吃读出（`status` 不展示，无副作用）。
- R6 回滚 = 把 5 处只读变体调用还原为加锁版即可，独立可回退。

## 七、实现偏差与最终定稿（编码后回填）

| # | 原文档 | 实际落地 | 原因 |
|---|---|---|---|
| 1 | `WantEatBoardResp.Item` 无版本字段 | **增加 `Integer version`** | 家长端状态流转必须回传 `expectedVersion`，否则无从做乐观锁；由 `boardItem(...)` 从 `ChildWantEat.version` 带出。 |
| 2 | 常吃快捷区"点击=标记想吃，**复用现有 `favorite()`**" | **新增 `quickFavorite()`**，不复用 `favorite()` | 快捷区的菜来自近 30 天历史，**可能不在今日餐单里**；后端 `markFavorite` 严格要求 `(dishType, dishId)` 命中当前菜单 typed refs，直接复用会 404。新方法先判"是否在当前餐单且 `selectable`"，不可点只 toast 提示、**不发请求**。卡片文案随之分三态：`今天已想吃 / 加入想吃 / 今日餐单暂无`。 |
| 3 | 未提快捷区失败处理 | **`loadFrequent()` 内部 try/catch 静默降级** | 快捷区是体验增强项，接口失败不应把整页打成错误态（`error` 会替换掉整个菜品列表）。 |
| 4 | 分类 chips 只暗示 CHILD | **CHILD 与 PARENT 都生效** | 家长维护菜单同样需要按分类找菜；`categoryName` 经 `DishResp` 增量字段已对两个角色的列表接口都可见（`dishResponse(dish, categoryNames)` 无值时单查兜底）。PARENT 端 `frequent` 恒为空数组，快捷区仅 CHILD 渲染。 |
| 5 | 未说明"分类聚合"实现位置 | 分类 chips 数据由页面 `buildCategories()` 从**当前来源可见菜品**聚合（首个固定为「全部」），`categoryId` 过滤在 `render()` 内先于关键词/清淡筛选执行 | 避免为分类聚合新增后端接口（对应设计稿决策 D6-B）。切换来源 Tab / 餐单来源时重置 `categoryId`。 |
| 6 | 测试：`CatalogFlowIT` 扩展 + 新增 `WantEatBoardIT` | 落地为 **`WantEatBoardIT` 7 用例**（区间分组、FAMILY 跨家庭隔离、越权 403、`from>to`/跨度>31 天 400、过期 `expired/expiredCount`、summary 去重与 count/dates、status 三态与 `expectedVersion` 409、frequent 排序与已删跳过、R6 并发不阻塞）；`CatalogFlowIT` 仅做去锁后的回归确认，未再加用例 | 避免单个 IT 类继续膨胀。 |
| 7 | R6 并发用例描述含糊 | 具体实现：另起线程 + `TransactionTemplate` 显式锁住 `life_menu_daily` / `life_dish` / `usr_child_profile` 行并挂住，主线程同时调 `GET /menu/daily` 断言 **200** | 只有真正持有行锁才能证明展示路径已去锁；若仍走 `FOR UPDATE` 该用例会超时失败（即回归哨兵）。 |
| 8 | 小程序测试计划未量化 | 新增 **5 个用例**（分类 chips 聚合与过滤、快捷区可点/不可点、快捷区失败降级、家长看板分组与状态流转、看板下架占位），小程序用例数 **48 → 53** | 覆盖 P1 新增交互。 |
| 9 | 乐观锁写法 | 沿用项目**手写范式**：`UpdateWrapper.eq("version", before)` + `setVersion(before+1)`，**不依赖** MyBatis-Plus `OptimisticLockerInnerInterceptor`（本项目未装配该插件） | 与 `ConfirmService.transition` 保持一致。 |
| 10 | — | `@Version` 注解在 `ChildWantEat` 上保留，但仅作字段语义标注，实际并发控制由上述手写条件更新承担 | 避免后来者误以为插件会自动生效。 |
