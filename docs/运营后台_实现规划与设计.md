## 1. 背景与目标

「成长星球」现有系统包含 C 端小程序（`growth-planet-miniapp`）与后端（`growth-planet`），后端已有 11 个业务域、163 条测试用例。运营侧此前缺少独立的后台管理能力。

本工程的目标是在**不破坏既有 C 端与既有测试**的前提下，交付一套独立的运营后台：

1. **账号体系隔离**：后台运营账号与 C 端微信账号物理隔离，token 互不可解，权限模型独立。
2. **细粒度 RBAC**：6 类角色 × 36 个资源 × 7 种操作的授权矩阵，落到 `sys_role_permission`。
3. **可审计**：登录成败、账号变更、权限变更均留痕（`sys_admin_login_log` + 复用 `sys_audit_log`）。
4. **全栈可交付**：后端接口 + 独立前端工程（Vue3），可本地启动联调。

## 2. 范围与里程碑

详细设计把运营后台拆为 11 个模块、3 个里程碑：

| 里程碑 | 范围 | 说明 |
|---|---|---|
| **A（P0 MVP）** | M0–M6 | 登录/工作台、运营看板、用户与权限、CMS 内容、业务数据、合规隐私、审计 |
| **B（P1 增强）** | M7–M9 | 通知触达、监控告警、配置中心 |
| **C（P2 进阶）** | M10 | 帮助中心与自助 |

**本轮已交付**：里程碑 A 的**地基纵切片**——认证隔离 + RBAC + 审计 + M0 登录/工作台 + M2 账号与角色权限。这是第一个端到端可验证的里程碑，后续 M1/M3/M4/M5/M6 复用同一套地基逐模块补齐。

## 3. 总体架构

```
┌────────────────────────┐        ┌────────────────────────┐
│  小程序 C 端（原生）      │        │  运营后台（Vue3+Vite）    │
│  growth-planet-miniapp │        │  growth-planet-admin   │
└───────────┬────────────┘        └───────────┬────────────┘
            │ /api/**  (C 端 JwtInterceptor)   │ /api/console/**(AdminJwtInterceptor)
            ▼                                  ▼
┌──────────────────────────────────────────────────────────────┐
│                    growth-planet（Spring Boot 4.1）            │
│  ┌───────────────┐   ┌───────────────┐   ┌────────────────┐  │
│  │ C 端接口        │   │ 后台接口        │   │ 共享基础设施      │  │
│  │ controller.*   │   │ controller.    │   │ Result/异常/审计  │  │
│  │                │   │   console.*    │   │ RequestContext  │  │
│  └───────┬───────┘   └───────┬───────┘   └────────────────┘  │
│          │  UserContext      │  AdminUserContext              │
│          ▼                   ▼                                │
│  auth-service …        AdminAuthService / AdminAccountService │
│          │                   │                                │
│          ▼                   ▼                                │
│   usr_user（C 端）      sys_admin_user（后台，独立）             │
└──────────────────────────────────────────────────────────────┘
                             │
                    MySQL（同一实例、不同表域）
```

**分层约定**（沿用既有工程规范）：

- 控制器只解析请求、调用服务、包装 `Result<T>`，不写业务逻辑。
- 服务层承载业务规则与事务（`@Transactional`），不依赖 HTTP 类型。
- 仓储层为 MyBatis-Plus `BaseMapper`，逻辑删除由全局配置 `deleteAt` 处理。
- 统一响应体 `Result<T>`、统一错误码 `ResultCode`（E-001…E-010 + E400/E404/E500）、全局异常 `GlobalExceptionHandler`。

## 4. 关键技术决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | **后台账号独立表** `sys_admin_user`，不复用 `usr_user` | 账号生命周期、风控、审计、口令策略与 C 端完全不同；物理隔离杜绝越权 |
| D2 | **独立 JWT 密钥与 issuer**（`jwt.admin-secret` / `growth-planet-admin`） | 后台 token 无法被 C 端解析，反之亦然（换密钥即双向不可解） |
| D3 | **独立前缀 `/api/console/**`**，而非 `/api/admin/**` | 既有 `MenuController` / `ComplianceController` 已占用 `/api/admin/**`，且被 6 个集成测试依赖（用 `usr_user(role=ADMIN)` 的 C 端 token）。换前缀实现**零破坏隔离** |
| D4 | **独立拦截器** `AdminJwtInterceptor`（仅 `/api/console/**`，放行 `/login`） | 与 C 端 `JwtInterceptor`（覆盖 `/**`，排除 `/api/console/**`）职责清晰、互不干扰 |
| D5 | **PBKDF2WithHmacSHA256** 口令哈希（JDK 内置，salt 随机 16B，迭代 65536） | 不引入 spring-security 即可满足口令安全；避免为登录功能拉起整条安全过滤链 |
| D6 | **SA 旁路**：超级管理员不落 `sys_role_permission`，运行时 `isSuperAdmin()` 直接放行 | 避免为 SA 写 36×7=252 条冗余授权行；矩阵接口对 SA 回显全量授权 |
| D7 | **`token_version` 单点失效**：改密 / 禁用 / 登出时自增 | 后台为单人多端低并发场景，改密或禁用后让既有 token 立即失效，无需引入 Redis 黑名单 |
| D8 | **逻辑删除字段纳入唯一键**（`uk_admin_username(username, delete_at)` 等） | 与既有表约定一致，软删后可重建同名账号而不撞键 |
| D9 | **分页不依赖插件**：`selectCount` + `LIMIT offset,size` 手写 | 既有工程未装配 `PaginationInnerInterceptor`，沿用既有分页写法保持一致 |
| D10 | **首个 SA 由启动器播种**（`AdminDataInitializer`，幂等） | 无需人工执行 SQL 即可引导系统；生产默认弱口令打 WARN 强制提醒 |

### 5.4 `sys_admin_login_log` 登录流水

### 6.4 鉴权执行链

1. `AdminJwtInterceptor#preHandle`：解析后台 token → 校验账号 `ACTIVE` 与 `token_version` → 载入角色权限点集合 → 注入 `AdminUserContext` → 校验 `@AdminRequireRole`（如声明）。
2. 服务层 `AdminUserContext.requirePerm(resource, action)`：SA 直接放行；否则查权限点集合，缺失抛 `E-009(403)`。
3. `afterCompletion`：清理 ThreadLocal，避免线程复用串号。

## 7. 接口清单（`/api/console/**`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/console/auth/login` | 放行 | 账号密码登录，返回 token + 身份 + 权限点 |
| POST | `/api/console/auth/logout` | 需登录 | 登出，`token_version + 1` 使旧 token 失效 |
| GET | `/api/console/auth/me` | 需登录 | 当前管理员身份与权限点（前端按钮级鉴权） |
| GET | `/api/console/workbench` | 工作台首页:view | 概览 KPI + 待办入口（M0） |
| GET | `/api/console/accounts` | 后台账号:view | 账号分页列表（关键字过滤） |
| POST | `/api/console/accounts` | 后台账号:create | 新建账号 |
| PUT | `/api/console/accounts/{id}` | 后台账号:edit | 编辑账号（密码留空=不改，改密则旧登录失效） |
| PUT | `/api/console/accounts/{id}/status` | 后台账号:edit | 启用/禁用（禁用即时失效） |
| POST | `/api/console/accounts/{id}/password` | 后台账号:edit | 重置密码 |
| GET | `/api/console/roles` | 角色权限:view | 角色列表（含授权点数） |
| GET | `/api/console/roles/permissions?roleCode=` | 角色权限:view | 某角色「资源 × 操作」权限矩阵 |

**错误语义**：未登录/失效 → `E-001(401)`；越权 → `E-009(403)`；参数非法 → `E-400(400)`；资源不存在 → `E-404(404)`。

## 8. 前端工程规划（`growth-planet-admin`）

- **技术栈**：Vue 3 + Vite + Element Plus + Vue Router + Pinia。
- **Base URL**：由环境变量注入，默认 `/api/console`（开发经 Vite 代理到后端 `19100`）。
- **token 存储**：内存 + `sessionStorage`（**禁止** localStorage / URL 参数），401 时清理并跳登录。
- **页面（本轮）**：
  1. 登录页 → `/api/console/auth/login`
  2. 主布局（侧边栏按权限点渲染菜单 + 顶栏显示角色/登出）
  3. 工作台（KPI 卡片 + 待办列表）
  4. 账号管理（列表 + 新建/编辑 + 启停 + 重置密码）
  5. 角色权限（角色列表 + 只读权限矩阵）
- **按钮级鉴权**：以 `/auth/me` 返回的权限点集合驱动 `v-if`。

## 10. 风险与回滚点

| 风险 | 影响 | 缓解 |
|---|---|---|
| 后台接口误开放到 C 端前缀 | 越权 | 已固定 `/api/console/**`；`AdminJwtInterceptor` 独立密钥，C 端 token 不可解（已测） |
| 生产沿用默认弱口令 | 账号被爆破 | `AdminDataInitializer` 在 prod 检测默认密码并打 WARN；建议 `CONSOLE_BOOTSTRAP_PASSWORD` 覆盖 |
| 新增后台表影响既有测试 | 回归 | 迁移仅新增 4 表、不改既有表；`schema-locations` 追加；已跑回归 |
| 权限矩阵播种被覆盖 | 配置漂移 | 播种按**角色粒度**幂等（角色已有权限则整体跳过），不覆盖后续手工调整 |
| SA 无授权行导致矩阵为空 | 展示异常 | 矩阵接口对 SA 回显全量授权（代码内特判） |

**回滚点**：本次为**纯新增**（4 张新表 + 新包 `controller.console` + 新服务/拦截器），不改任何既有表结构与既有接口。如需回滚，删除后台相关类与 `v008_admin.sql` 登记即可，C 端与既有测试不受影响。**未做任何 commit / push**。
