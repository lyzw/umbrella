# 学生端（儿童）菜单与主页优化 — 分析、规划与设计

> 修订日期：2026-09-22 · 范围：成长星球小程序「儿童账号（CHILD）」的菜单（底部导航）与主页（含各 tab 首屏）简化重构。
> 本文为**规划与设计文档**，编码前需经确认。家长端（PARENT）不在本次范围。

---

## 一、背景与问题诊断

产品定位：面向 6–12 岁儿童及家庭的成长应用。当前小程序已区分两套底部导航：

- 孩子端 `childTabs`：`点餐 / 家务 / 成长 / 我的`
- 家长端 `parentTabs`：`首页 / 审批 / 钱包 / 我的`

**表面分了两套，但"学生端菜单与家长端一致"的根因不在 tab 文案，而在"功能内容"——孩子端首页和「我的」几乎复用了家长的成人功能清单。** 具体证据（来自 `pages/home/index.wxml`、`pages/profile/index.wxml`）：

1. 孩子端首页功能列表 = 我的确认单 + 虚拟零花钱 + **家庭与绑定** + 日程提醒 + 勋章墙 + 健康打卡。其中「家庭与绑定」「虚拟零花钱（额度/流水）」「日程提醒」对孩子无意义甚至是越权入口。
2. 「家庭与绑定」在孩子端出现 **两处**（首页列表 + 「我的」列表），孩子既不需要也无法正确管理家庭关系/授权。
3. 底部「成长」tab 是空的"幼苗"占位页（`growth-panel` 仅一句文案 + 一个跳勋章的按钮），没有独立价值，浪费一个 tab 位。
4. 架构不一致：`家务` tab 点击后 `wx.navigateTo` 跳到独立 `chore` 页（该页再自行渲染 `app-nav`），而 `点餐/成长/我的` 是 `home` 页内子视图（`setData` 切换）。孩子在两套交互里跳来跳去。
5. 首屏优先级错配：孩子每天来的主因是"今天吃什么/我想吃"，但首屏 hero 之后才是功能黄页，「想吃 / 心愿菜单」被埋在深层 `menu` 页里。
6. 语言成人化：`确认单`、`额度`、`流水`、`家庭与绑定`、`日程提醒` 等术语对低龄儿童不友好。

## 二、学生用户特征（6–12 岁，分龄）

| 维度 | 特征 | 对设计的要求 |
|---|---|---|
| 认知 | 具体形象思维为主，文字阅读力有限 | 大图标、大色块、图片优先、少文字 |
| 注意力 | 集中时间短，易分心 | 首屏只答一件事；少层级 |
| 决策 | 选项过多会焦虑/放弃（选择悖论） | 聚焦核心、引导式而非菜单式 |
| 动机 | 游戏化驱动（积分/勋章/连击/等级）、即时正反馈、角色代入 | "小当家"人设、星星/金币、连击、成就解锁 |
| 自主边界 | 能做：点餐、标记想吃、做家务、打卡；不应管：家庭关系、隐私授权、钱包额度、菜单发布 | 最小权限，移除成人入口 |
| 安全 | 不暴露成人配置与敏感数据 | 越权页对 CHILD 直接拦截 |
| 场景 | 碎片化、家长在场或独自、弱网低龄容错 | 操作可逆、反馈即时、容错提示 |

### 3.3 底部导航与核心页

- `childTabs`：`点餐 / 家务 / 成长 / 我的` —— 方向对，但「家务」架构割裂、「成长」为空占位。
- `menu` 页（点餐）：对孩子已较友好（今日家庭/学校餐单、推荐/常吃快捷卡、想吃标记、心愿菜单 P3）。**应作为孩子端唯一主入口**，而非深埋在首页功能列表下。
- `chore` 页（家务）：孩子视图（任务库认领/提交）已可用，应并入「任务」tab。
- `health` 页（打卡）：孩子视图可用，应并入「任务」tab。

## 四、优化目标与原则

1. **"吃"是唯一主因**：点餐 tab = 孩子端首页，首屏只回答"今天吃什么 / 我想吃"。
2. **游戏化激励替代功能黄页**：用「任务 / 成长」承载勋章、打卡、零花钱余额，取代成人功能清单。
3. **最小权限**：从孩子端彻底移除 家庭与绑定、钱包管理、隐私/同意、菜单发布/我的菜品、日程配置。
4. **视觉与语言儿童化**：大图标大色块、游戏化称呼（小当家、星星、连击）、正向激励文案。
5. **架构统一**：4 个 tab 统一为 `home` 子视图（`setData` 切换），深层详情（任务详情、勋章详情、余额明细）再 `navigateTo`，消除 navigateTo 割裂。

## 五、学生端菜单重构方案

### 新底部导航（孩子端，4 tab，全部 home 子视图）

| key | 名称 | 图标 | 职责 | 内容来源 |
|---|---|---|---|---|
| `meal` | 点餐 | 🍱 | 今日家庭餐单 + 学校餐单 + 推荐/常吃 + 想吃 + 心愿菜单 + 爸妈确认状态 | 现 `menu` 页 + `confirmation` 状态条 |
| `task` | 任务 | 🎯 | 家务任务认领/提交 + 健康打卡（连续天数） | 现 `chore` 孩子视图 + `health` |
| `growth` | 成长 | 🏅 | 勋章墙 + 连续天数总览 + 零花钱只读余额 + 成就进度 | 现 `medal` + `wallet`(只读) + `health` 概览 |
| `me` | 我的 | 👦 | 口味偏好 + 通知 + 退出 | 现 `profile`(孩子) + `notices` |

> 文案/图标在 `components/app-nav/index.js` 的 `childTabs` 调整（`家务`→`任务` 🎯；`成长`→保留但落地真实内容）。

### 移除/隐藏（孩子端永不出现）

- `family`（家庭与绑定）—— 完全不进孩子端
- `wallet` 管理视图（额度/流水配置）—— 仅只读余额出现在「成长」
- `privacy`（同意与数据权利）—— 不进孩子端
- `dish-manage`（我的菜品）、菜单发布 —— 家长专属（当前已正确，保持）
- `schedule`（日程配置）—— 当前不进孩子端；V2 以只读「今日安排」卡片补回
- `confirmation` 全页入口 —— 降级为 `meal` 内轻量状态条

## 六、学生端主页（点餐 tab 首屏）重构

**设计原则：首屏只答"今天吃什么 / 我想吃"，游戏化、大图卡、零成人术语。**

布局（自上而下）：

1. **顶部轻量条**：问候（"嗨，小当家～"）+ 今日日期 + 成长小进度（🏅 N 枚 / 🔥 连续 M 天）。
2. **Hero 卡**：今日餐单摘要（家庭 + 学校各几餐已发），大按钮「去点餐 / 看看今天吃什么」。
3. **快捷区（横滑大卡）**：
   - 「今天吃什么？」推荐菜（避开过敏/忌口，点一下加入想吃）
   - 「我爱吃」常吃菜（点一下加入想吃）
4. **心愿菜单卡**：今天的心愿（已选 X 道 / 提交给爸妈 / 撤回）。
5. **爸妈确认状态条**（游戏化语言）：已提交 → 爸妈在看 → 已同意 → 今天就能吃到。
6. **健康打卡小提醒**（可选，V1 放任务 tab；此处给"今日还没喝水打卡"轻提示）。

**不出现**：家庭与绑定、钱包额度、日程、确认单全页、任何"管理"字样。

## 七、各 tab 页面简化要点

### 任务 tab（task）
- 上半：家务任务库（认领 / 提交完成）+ 我的家务（状态）。
- 下半：健康打卡今日任务（喝水 / 睡眠 / 运动，连续天数 + 连击动效）。
- 完成得星星/金币即时动效，强化游戏化。

### 成长 tab（growth）
- 勋章墙（核心，保留现有 `medal` 体验）。
- 连续打卡天数总览（来自 `health` 概览）。
- 零花钱**只读余额**（大数字 + "再完成 X 个任务就能攒到 Y"），不暴露额度/流水管理入口。
- 把空"幼苗"占位替换为真实成就总览（最近点亮、距离下一枚还差什么）。

### 我的 tab（me）
- 口味偏好（孩子可填不喜欢/口味；过敏仍由家长维护，保持现有约束）。
- 通知中心。
- 退出登录。
- **移除**家庭与绑定、钱包管理。

## 八、权限与架构落地

1. **统一壳**：`home` 页 `CHILD_HOME_TABS = ['meal','task','growth','me']`；`changeTab` 改为 `setData` 内联子视图（task 不再 navigateTo）。深层详情（任务详情/勋章详情/余额明细）从对应 tab 内 `navigateTo` 至现有 `chore`/`medal`/`wallet` 页。
2. **越权拦截**：`pages/family`、`pages/privacy`、`pages/dish-manage` 对 `CHILD` 在 `onShow` 经 `ui.guard` 重定向回 `home`；`ui.go` 对 CHILD 屏蔽这些 page key。
3. **文案儿童化**：`确认单`→「爸妈确认」、`额度/流水`→不出现、`家庭与绑定`→移除。

## 十二、实现记录（2026-09-22，按推荐落地）

### 已落地
- **底部导航**：`app-nav` 孩子端 `childTabs` 由 `点餐/家务/成长/我的` 改为 `点餐/任务/成长/我的`（`家务`→`任务`，key `chore`→`task`）。
- **点餐（=孩子首页）**：移除成人功能黄页（确认单全页/钱包/家庭与绑定/日程/勋章/健康），改为「今日餐单摘要 + 今天吃什么(推荐) + 我爱吃(常吃) 横滑卡 + 心愿菜单卡 + 爸妈确认状态条」；推荐/常吃卡可一键加入「想吃」（复用菜单页安全校验）。
- **任务（=原 chore 页）**：孩子端在原「家务认领/我的家务」下**并入今日健康打卡**（打卡项 + 连续天数 🔥 + 查看打卡日历入口）。
- **成长**：移除空「幼苗」占位，改为「勋章墙 + 连续打卡天数 + 零花钱只读余额」；余额来自 `/wallet/overview`，不暴露额度/流水管理。
- **我的**：孩子端移除「家庭与绑定 / 零花钱与额度 / 勋章墙 / 同意与数据权利」入口，仅保留「口味偏好 + 通知中心 + 退出」。
- **越权拦截**：`family`、`schedule` 页 `onShow` 加 `ui.guard(this, 'PARENT')`，孩子直接访问被重定向回首页（`privacy`、`dish-manage` 此前已拦截）。
- **确认单**：全页入口降级为「点餐」内状态条，深层详情页仍可从状态条进入。

### 一处务实偏差（相对原方案 §八.1）
原方案希望 4 个 tab 全部为 `home` 内联子视图、彻底消除 `navigateTo` 割裂。实际落地时：**点餐/成长/我的为 home 内联子视图；「任务」tab 仍 `navigateTo` 到 `chore` 页**（即原家务页，现已并入健康打卡）。理由：家务页本就是孩子的独立任务页、且被家长端复用，内联进 home 会复制大量逻辑并显著抬高回归风险；本次以「内容简化 + 移除成人入口」为核心目标，导航割裂为次要体验项，后续可再统一。
