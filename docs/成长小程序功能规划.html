「成长星球」儿童生活与学习小程序 · 功能规划

面向 11 岁、六年级孩子，从「孩子自主点餐」起步，逐步扩展到生活自主与学习成长两大版图。本文档含整体功能架构、分阶段核心功能清单与演进优先级安排。

微信小程序 Java + MySQL 儿童 / 家长 / 后台 三角色 分阶段演进

命名说明：「成长星球」为产品暂定名（Umbrella），首期上线的点餐模块命名为「小当家·点餐」。名称可按品牌诉求调整，不影响架构。

一、目标用户与关键设计原则

主角：11 岁六年级小学生。认知与操作能力：能独立阅读图文、点按操作；不擅长长表单与复杂设置；对游戏化、勋章、动画敏感；自我保护意识弱（需家长护栏）。

关键设计原则：

  • 家长护栏优先：不做真实支付，消费走"虚拟零花钱"记账；对外联系、位置、内容发布经过家长授权或审批流；儿童端不做裸露的聊天/社交/定位。
  • 大字号 + 强图标 + 语音辅助：降低识字与输入门槛；关键操作支持语音与图片。
  • 即时正反馈：每完成一件事给予勋章/动画/进度，强化自主感与成就感。
  • 本地化与个性化：学校食堂/家庭餐厅、口味忌口偏好、适龄理财观念引导、多语言可选、可对接本地生活服务（不限定城市）。
  • 隐私合规：遵循儿童个人信息保护相关法规，最小化采集、家长明示同意、可撤回。

二、整体功能架构（三角色 + 三层模块）

① 儿童端（主角）

  • 小当家·点餐
  • 我的零花钱
  • 家务小任务
  • 健康打卡
  • 我的课表/作业
  • 错题本 / 阅读
  • 成长树 / 勋章
  • AI 小问号

② 家长端（监护人）

  • 家庭与孩子绑定
  • 支付与额度设置
  • 审批流（点餐/任务）
  • 消费与成长看板
  • 内容白名单
  • 安全与权限

③ 后台（运营）

  • 菜单管理（当日菜单配置 / 展示）
  • 任务 / 书单库
  • 勋章 / 活动配置
  • 内容审核
  • 数据与风控

能力中台

  • 账号 / 家庭关系
  • 支付网关
  • 通知（订阅消息 + 站内通知中心 + 家长短信兜底）
  • AI 服务
  • 数据看板
模块版图（按演进）： 生活侧 = 点餐 → 零花钱 → 家务 → 健康/日程 → 购物/出行； 学习侧 = 课表 → 作业 → 错题本 → 阅读 → 知识百科； 收敛层 = 成长档案 + 勋章激励 + AI 小助手（贯穿全部阶段）。

三、分阶段演进路线（Roadmap）

P0 地基第 1–2 月
账号/登录/家庭绑定/框架 + 虚拟钱包地基/通知中台/合规同意
P1 点餐起步第 2–4 月
小当家·菜单展示与确认 MVP（额度护栏+站内通知）
P2 生活自主第 5–8 月
零花钱/家务/健康/日程 + 奖励兑换/二级监护人
P3 学习成长第 9–12 月
课表/作业/错题/阅读 + 教师角色与家校互通
P4 智能激励第 13–18 月
AI/成长树/多孩 + 成长洞察/数据删除导出

为什么从「点餐」起步？

① 高频刚需、每天可用，能快速养成使用习惯；② 天然需要「孩子决策 + 家长额度护栏（虚拟零花钱）」的护栏结构，正好验证三角色模型；③ 顺带建立消费记录与偏好，为后续零花钱、营养健康打地基；④ 正向反馈明显（孩子确认菜单 → 家长确认 → 完成），孩子成就感强，家长接受度高。

六、技术架构建议（Java + MySQL）

后端：Java 21 LTS + Spring Boot 4.1.1（Spring Framework 7、Jakarta EE 11、jakarta.* 命名空间、虚拟线程；与你 KidCode 的 Java 11 / 2.7.18 属不同代际，本新项目直接采用 21/4.1.1）；ORM 用 MyBatis-Plus（复杂报表/统计友好）；API 风格 RESTful + JWT（家长/儿童分权）。

数据库：MySQL 8.0；通用字段 create_time / update_time / deleted；枚举用 VARCHAR 在 Java 控制。缓存/会话用 Redis；订单通知用微信订阅消息 + 可选 MQ 解耦。

小程序端：微信小程序原生 或 Taro/uni-app（Vue/React 跨端）。前端非 Java，属独立工程。

支付与安全：不做真实支付，结算走虚拟零花钱记账 + 额度护栏；儿童所有对外动作走审批流；内容经后台审核；隐私最小化采集 + 家长明示同意。

核心数据模型（MySQL 关键实体）

采用业务域前缀（合并为 3 个主域，避免前缀过多）：usr_ 账户/家庭/成长基础（用户、家庭、成员、儿童档案、勋章、成长流水） · life_ 生活域（菜单、菜单确认、钱包零花钱、家务、健康） · edu_ 学习域（作业、错题、阅读）。

usr_child_profile年级、学校、忌口、口味偏好、头像

七、关键风险与合规

风险

  • 虚拟消费合规：仅虚拟零花钱记账 + 额度护栏，儿童端无任何真实支付能力；超额动作由家长异步复核（非实时拦截）。
  • 隐私采集红线：位置/人脸/OCR 需家长同意，可撤回。
  • 内容安全：AI 与 UGC 需审核，防不良信息。
  • 沉迷：游戏化适度，设使用时长提醒。

应对

  • 审批流 + 额度双控（额度内自动、超额异步复核），家长全可见。
  • 可验证监护人同意（家长实名/运营商三要素）+ 年龄识别；儿童数据单独存储。
  • 最小化采集 + 明示同意留痕 + 数据可导出/可删除（留存期限到期清理）。
  • 后台内容审核 + 敏感词/图像风控（覆盖 AI 与 UGC）。
  • 成长类激励替代纯消耗型玩法；兑换中心补上动机闭环。
