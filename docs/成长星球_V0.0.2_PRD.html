二、版本目标与范围

2.1 文档目的：在已上线的 V0.0.1（点餐 MVP）之上，结构化定义 P2 生活自主全量模块的需求，使研发、设计、测试可据此拆解 P2 开发任务。

2.2 业务目标（可量化）：

  • G1：跑通"赚→花→管"闭环——家务/任务奖励入账（收入）、点餐/购物/兑换扣减（支出）、家长看板统览，端到端成功率 ≥ 95%。
  • G2：维持零真实支付；新增购物清单、奖励兑换均走虚拟零花钱记账 + 家长护栏。
  • G3：跨场景消费额度一致——点餐 + 购物 + 兑换共享每日/每周支出上限，奖励收入不计入支出额度（避免"赚钱反而触发超额"的语义冲突）。
  • G4：二级监护人可在家长授权范围内行使审批，且不触碰额度修改、数据导出、解绑等高危操作。

2.3 非目标（本期不做）：真实支付/物流履约、教师角色与家校互通（P3）、课表/作业/错题/OCR（P3）、AI 小问号与成长树养成（P4）、多孩扩展 UI、个性化推荐、隐私工单自动化（P4）。

2.4 范围 In / Out

✅ 本期包含（In）

  • 零花钱管理 UI（余额看板、预算可视化、流水增强、发放入口）
  • 家务小任务（任务库、认领、完成确认、状态机、周期任务）
  • 健康打卡（打卡项、打卡提交、连续记录）
  • 日程提醒（家庭日程、儿童视图、提醒投递）
  • 购物清单（清单维护、确认审批、跨场景额度护栏）
  • 奖励兑换中心（奖励库、兑换、审核履约）
  • 二级监护人委托（邀请绑定、权限分级、时效撤销）
  • 基础勋章/成就服务（跨模块复用）

⛔ 本期不包含（Out）

  • 真实支付、真实物流/到店履约系统（实物奖励由家长线下履约+站内确认）
  • 教师角色、家校互通
  • 课表/作业/错题/OCR/阅读/百科
  • AI 小问号、成长树养成、个性化推荐
  • 多孩切换 UI、隐私工单全自动处理

五、用户故事与验收（精选）

US-1（儿童） 作为孩子，我想要认领家务并完成后获得零花钱，以便体验"赚钱"。

  • AC1：可浏览家长发布的任务并认领，生成任务实例。
  • AC2：标记完成后家长确认，虚拟币与勋章同事务入账（F-030/F-031/F-048）。
  • AC3：余额实时更新，收入不计入每周支出额度（F-041）。

US-2（儿童） 作为孩子，我想要把想买的东西加入清单并请爸妈确认，以便用零花钱"购买"。

  • AC1：可维护购物清单（名称/预估虚拟价/图片）。
  • AC2：提交后家长审批，复用超额异步复核；同意后扣减虚拟币（F-040）。
  • AC3：购物与点餐共享每周额度，不会因点餐已花光而静默超支（F-041）。

US-3（儿童） 作为孩子，我想要用零花钱兑换奖励，以便获得正反馈。

  • AC1：浏览奖励库，余额充足时可兑换（F-043）。
  • AC2：实物奖励家长确认发放；特权类立即生效（F-044）。

US-4（家长） 作为家长，我想要委托祖辈临时看护审批，以便我不在时孩子也能用。

  • AC1：可邀请二级监护人并限定范围（F-045/F-046）。
  • AC2：委托人只能审批点餐/家务/购物，不能改额度/导出（E-009 复用）。
  • AC3：到期或撤销后自动降级（F-047）。

8.2 冲突与一致性检查（已规避）

  • 额度语义冲突：奖励收入 vs 消费支出。已裁定奖励为"收入"不计入每周支出额度（F-041），避免"赚钱触发超额"的歧义。
  • 流水混用：统一 life_allowance_log.type 枚举（CONSUME_DEDUCT/REWARD_ADD/MANUAL_GRANT/EXCHANGE_DEDUCT），各场景不混写。
  • 状态机冲突：家务状态机（F-031）与点餐状态机（F-019）独立实体、独立状态集合，无字段/语义重叠。
  • 权限越界：二级监护人所有操作叠加委托范围过滤，高危操作（改额度/导出/解绑）对委托人不可见且返回 403，复用 V0.0.1 E-009。
  • 隐私越界：健康打卡数据采集绑定 F-007 同意，撤回后停采，纳入 F-012 出口，不新增独立同意链路。
  • 并发扣减：家务奖励发放、购物/兑换扣减均复用 V0.0.1 钱包行锁+版本校验，防止跨场景并发超扣。
