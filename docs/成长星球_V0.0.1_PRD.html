二、版本目标

2.1 文档目的：将"成长星球"首个可上线版本（P0 地基 + P1 点餐）的需求结构化、无歧义化，使研发、设计、测试、运营拿到后可直接拆解任务。

2.2 业务目标（可量化）：

  • G1：跑通"孩子确认今日菜单 → 家长额度护栏 → 虚拟记账 → 正向反馈"最小闭环（端到端成功率 ≥ 95%）。
  • G2：V0.0.1 内零真实支付，儿童端无任何真实资金能力。
  • G3：监护人同意留痕 100% 覆盖（无同意不得采集儿童数据）。
  • G4：家长审批平均响应 ≤ 异步（不强制实时），通知触达率 ≥ 99%（三通道兜底）。

2.3 非目标（本期不做）：真实支付/商户接单、家务/健康/课表/作业/错题/AI/成长树养成、教师角色、多孩 UI 切换、OCR、个性化推荐、数据导出完整能力（仅留入口，P4 完善）。

5.1 关键功能点详细说明（节选）

F-003 儿童档案引导

  • 输入：昵称（文本）、年级（选择，默认六年级）、学校（文本/选择）、忌口与口味（多选 chip：如海鲜/辣/葱蒜/过敏物）。
  • 输出：usr_child_profile 记录；状态置「待家长绑定」。
  • 业务规则：分步每屏一项 + 进度条；未补全时每次启动顶部黄条「补全档案领勋章」引导；档案未补全不影响浏览，但写操作灰显。
  • 原型：欢迎页→角色选择→档案分步引导（5 屏）→完成。

F-007 家长身份确认 + 授权（合规红线）

  • 功能描述：可验证监护人同意 + 年龄识别 + 同意留痕；交互必须明确、不可默认勾选。
  • 业务规则：独立 checkbox（不与登录合并）；触发可验证核验（家长实名 / 运营商三要素其一）→ 年龄识别（<18 不可作监护人）；核验通过写 guardian_status=VERIFIED + 时间戳；家长可随时撤回，子账号相关采集即时降级。
  • 异常处理（详见第八章）：核验失败（非监护人/信息不符）→ 明确原因，提供「换账号/联系客服」，**绝不**静默通过。
  • 待确认（R-05）：「可验证监护人核验」是否纳入 V0.0.1，或先用「家长微信绑定 + 明示同意 + 自报年龄」作为 MVP，核验作后续增强。

F-009 家长额度设置（最小可行，前移）

范围裁定：规划文档将"零花钱管理 UI"置于 P2，但 V0.0.1 点餐护栏必须有额度来源。本 PRD 裁定：将"单笔 / 每日 / 每周上限设置"以最小可行形态前移纳入 V0.0.1（F-009），其余预算可视化/图表留 P2。初始默认值：单笔 ¥30、每日 ¥30、每周 ¥150（可配置，待确认 A-默认值）。
  • 输入：家长设单笔上限、每日上限、每周上限（数值）。
  • 输出：life_allowance_rule（按 child_id 维度）。
  • 规则：提交确认单时按"单笔 ≤ 单笔上限 且 当日累计+本单 ≤ 每日上限 且 当周累计+本单 ≤ 每周上限"判定额度内/超额。

F-018 / F-019 菜单确认与额度状态机（核心）

口径统一（解决规划与交互文档矛盾，见审查 R-01）：
① 儿童提交确认单 → 状态 待家长确认（系统做额度预校验但不立即扣减）；
② 系统判定 is_over_limit：额度内 → 家长「同意」为一键通过；超额 → 状态显示 复核中（超预算），家长须显式确认放行；
③ 家长「同意」→ 此时才扣减虚拟零花钱 → 已完成；
④ 家长「拒绝」→ 已驳回，儿童见温和说明，可改后重提（回 待家长确认 草稿）。
即："额度内自动扣减"理解为"家长同意后系统自动完成扣减（无需二次校验）"；扣减动作统一发生在家长「同意」之后。

F-014 / F-015 后台菜品库与当日菜单（V0.0.1 后台范围）

  • F-014：运营维护 life_dish（名称、虚拟价格、热量、图片、标签如辣度/忌口类）；分类 life_dish_category。
  • F-015：运营按"学校 + 日期 + 餐段（早/午/晚）"配置当日菜单，关联菜品。V0.0.1 模型建议用 life_menu_daily（替代规划中的 life_restaurant，见 R-07），因为无多商户营运。

六、用户故事与验收标准

格式：作为【角色】，我想要【能力】，以便【价值】。每则附可测试验收标准（AC）。

US-1（儿童） 作为 11 岁孩子，我想要用微信一键登录并创建我的档案，以便快速开始使用点餐功能。

  • AC1：点击「微信一键登录」后弹出微信授权，成功建立匿名会话。
  • AC2：选择「我是孩子」后进入分步档案引导（昵称/年级/学校/忌口/口味），每屏一项并显示进度。
  • AC3：档案保存后状态为「待家长绑定」，可浏览菜单但写操作灰显直至绑定完成。

US-2（家长） 作为家长，我想要创建家庭并邀请孩子加入，以便管理孩子的账户与护栏。

  • AC1：家长端可「创建家庭」并生成 6 位邀请码/二维码，标注 24h 有效。
  • AC2：儿童端输入码或扫码后提交绑定申请，提示「已发送，等爸妈确认」。
  • AC3：家长在审批列表确认监护关系（子/女）后，双方收到「家庭已连通」通知，孩子获入学勋章。

US-3（家长） 作为家长，我想要确认我是孩子的监护人并同意信息处理，以便合规且解锁儿童数据采集。

  • AC1：《儿童个人信息处理同意书》可展开全文，独立 checkbox 不可与登录合并。
  • AC2：勾选后触发可验证核验（依 R-05 方案），通过写 guardian_status=VERIFIED + 时间戳。
  • AC3：核验失败给出明确原因与「换账号/联系客服」，绝不静默通过。
  • AC4：家长撤回同意后，对应采集能力即时降级并留痕。

US-4（家长） 作为家长，我想要设置孩子的零花钱额度上限，以便孩子点餐不会超支。

  • AC1：家长可为指定孩子设置单笔/每日/每周上限，保存写入 life_allowance_rule。
  • AC2：未设置时采用可配置默认值（单笔 ¥30/每日 ¥30/每周 ¥150）。
  • AC3：额度规则变更后，下一张确认单即按新规则校验。

US-5（儿童） 作为孩子，我想要浏览今天的菜单并标记想吃的菜，以便爸妈知道我的口味。

  • AC1：点餐 Tab 首屏按餐段（早/午/晚）折叠展示当日菜单，大图卡含虚拟价格/热量/忌口标识。
  • AC2：支持筛选（全部/我爱吃/低糖/无辣/忌口过滤）。
  • AC3：可标记「今天想吃」，家长端可见。

US-6（儿童） 作为孩子，我想要向爸妈确认今天的菜单，以便他们帮我记账。

  • AC1：在确认页勾选菜品 + 份量（±1）+ 备注 chip（少糖/少葱/不要辣），忌口自动带入、过敏项灰显不可选。
  • AC2：预览展示合计虚拟金额、预计扣减后余额、营养小结。
  • AC3：点「告诉爸妈」生成 life_menu_confirm，状态置「待家长确认」。

US-7（家长） 作为家长，我想要审批孩子的菜单确认单，以便掌握消费并守护预算。

  • AC1：审批卡片展示菜单明细、金额、孩子备注、预计余额。
  • AC2：额度内 → 「同意」一键通过；超额 → 强制出现额度说明，须显式确认放行。
  • AC3：家长「同意」后系统扣减虚拟零花钱并通知孩子「爸妈同意啦/已完成」。
  • AC4：家长「拒绝」后孩子见温和说明（如"今天先选便宜点的好不好？"），可改后重提。

US-8（后台运营） 作为运营，我想要配置每日菜单，以便孩子能看到当天菜品。

  • AC1：可在后台维护菜品库（图文/虚拟价格/热量/标签）。
  • AC2：可按学校+日期+餐段发布当日菜单，发布后儿童端点餐页可见。

US-9（家长/合规） 作为家长，我想要撤回同意或导出/删除儿童数据，以便行使合规权利。

  • AC1：设置-安全与权限可撤回某类采集同意，系统即时降级并留痕。
  • AC2：数据出口入口可触发生成儿童数据包（V0.0.1 为入口 + 基础导出，完整能力 P4）。

E-007并发扣减同一余额多笔同时扣乐观锁/事务，串行化—记录并发冲突
E-008通知发送失败订阅未授权/短信失败三通道降级，至少站内可达站内红点保底记录通道失败
E-009越权访问访问非本家庭数据401/403 拒绝「无权限」记录越权尝试（安全）
E-010家长撤回同意撤回某类采集即时降级能力「已关闭相应能力」留痕时间戳

10.2 数据权限规则

  • 所有查询按 family_id 过滤；儿童仅能访问 child_id = 本人 的记录。
  • 家长仅能访问其 usr_family_member 关联家庭下的成员数据。
  • 后台运营访问儿童数据须脱敏，且操作留审计日志。

10.3 权限变更流程

家长撤回同意 → 系统即时降级对应采集能力 → 写入同意日志（时间戳）。账号注销走二次确认 + 留存期限说明 → 到期自动清理。

十一、非功能需求

11.1 性能要求

指标目标说明
菜单首屏加载≤ 1s（骨架屏）小程序内，弱网友好
接口 P95 响应≤ 300ms常规读写
通知触达≥ 99%三通道兜底，站内保底
并发单家庭低频；支持千级家庭同时在线虚拟记账用事务/乐观锁

11.2 兼容性要求

  • 微信小程序：iOS / Android 主流版本；基础库版本 ≥ 指定基线（待定）。
  • 小程序主包 ≤ 2MB，总包 ≤ 20MB（注意 TTS/资源体积）。
  • 家长端同一小程序按角色路由，无需独立安装。

11.3 安全要求

  • JWT 分权（child/parent/admin），token 失效与刷新机制；敏感接口签名/防重放。
  • 虚拟钱包扣减须事务 + 乐观锁（version 字段），防止并发超扣。
  • 儿童数据加密存储，最小化采集，明示同意留痕。
  • 越权访问统一 401/403 + 安全日志；后台操作全审计。
  • 不采集儿童真实位置/人脸（V0.0.1）；OCR/位置待 P2+ 且需同意。

11.4 可用性 / 无障碍（WCAG 2.2 AA）

  • 正文对比度 ≥ 4.5:1，UI 组件 ≥ 3:1；状态配图标+文字，不纯靠颜色。
  • 触控目标 ≥ 44×44px；主操作更大。
  • 语音辅助（P2 可选）；错误文案儿童可懂，给明确下一步。
  • 动效仅 transform/opacity，尊重系统「减少动态效果」。
