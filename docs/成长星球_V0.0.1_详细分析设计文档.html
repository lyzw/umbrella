3.4 用户故事与可测试验收要点（US-1..9，精简引用 PRD 六）

US-1（儿童/家长） 最小登录→角色→绑定申请→家长同意→绑定→家长建档；无同意不展示档案表单、不存草稿/埋点；档案只有INCOMPLETE/COMPLETE，family_id必填。

US-2（家长） 创建家庭并邀请孩子。AC：生成 6 位码/二维码，24h 有效；儿童提交申请提示"等爸妈确认"；审批后双方收"家庭已连通"通知 + 入学勋章。

US-3（家长） 确认监护人并同意信息处理。AC：《同意书》可展开、独立勾选；通过写 guardian_status=SELF_ATTESTED；失败给原因不静默；撤回即时降级。

US-4（家长） 设零花钱额度上限。AC：可设单笔/每日/每周并写入 life_allowance_rule；未设用默认 30/30/150；变更后提交及待审单审批均按最新规则。

US-5（儿童） 浏览今日菜单并标记想吃。AC：按餐段折叠 + 大图卡（虚拟价格/热量/忌口）；支持筛选；可标记"今天想吃"。

US-6（儿童） 向爸妈确认今日菜单。AC：勾选菜品+份量±1+备注 chip；预览合计虚拟额与预计余额；点"告诉爸妈"生成确认单 status=PENDING。

US-7（家长） 审批菜单确认单。AC：卡片看明细；额度内一键同意；超额强制说明须显式放行；同意后扣减并通知孩子"已完成"；拒绝给温和说明可重提。

US-8（后台） 配置每日菜单。AC：维护菜品库（图文/虚拟价格/热量/标签）；按学校+日期+餐段发布当日菜单，发布后儿童端可见。

US-9（家长/合规） 撤回同意或导出/删除数据。AC：设置-安全与权限可撤回某类采集，即时降级留痕；数据出口入口可触发生成儿童数据包（V0.0.1 入口+基础导出，首版含可办理的导出/删除工单）。

四、角色与权限模型

4.1 三角色与 JWT 分权

角色标识核心能力（V0.0.1）数据可见范围
儿童ROLE_CHILD建档、加入家庭、浏览菜单、确认菜单、看本人状态/流水仅本人档案、本人确认单与流水
家长ROLE_PARENT建家庭、邀绑定、设额度、审批确认单、看消费看板、撤回同意/数据出口所绑定家庭的成员及其数据
后台运营ROLE_ADMIN菜品库、当日菜单配置、内容/风控（P1 起）全量运营数据（脱敏）
鉴权实现（引用 PRD 十）：JWT 区分 child / parent / admin；token 含 user_id + role + family_id[]；敏感接口签名/防重放；token有效30分钟，过期重新wx-login并加载最新权限。

4.2 数据隔离规则（family_id + child_id）

  • 查询强制过滤：所有业务查询按 family_id 过滤；儿童仅能访问 child_id = 本人 的记录（写入/读取均以 JWT 中身份为准，不得客户端传参越权）。
  • 家长维度：家长仅能访问其 usr_family_member 关联家庭下的成员数据；审批/记账以家长身份留痕。
  • 后台维度：运营访问儿童数据须脱敏，且操作写 sys_audit_log。
  • 越权处理：访问非本家庭数据 → 统一 401/403（E-009）+ 安全日志。
  • 同设备视图（Q-07）：独立CHILD/PARENT账号；家长儿童视图仅只读预览，不改role、不代理提交。无儿童独立账号的方案需先补actor/subject模型并经产品确认。

五、数据结构（数据字典（迁移待验证））

原16表字典加新增sys_privacy_request设计，共17个逻辑对象，尚未与应用/迁移脚本逐项核对。通用字段create_time/update_time/delete_at保留；金额DECIMAL(10,2)，非真实货币。钱包采用行锁及事务，version作附加条件校验。增量完整字段与迁移顺序见修订基线第4节。

唯一键与删除：openid、确认单号、钱包/规则child_id、流水和请求幂等键不可因软删除复用；成员关系和同日菜单更新原记录。禁止统一添加delete_at到全部唯一键。普通业务过滤有效行，审计与幂等检查仍须覆盖历史记录；名称复用约束逐表设计。

六、接口定义（RESTful + JWT）

按域分8组接口；统一响应{code,data,message,requestId}，code=0成功，错误E-001至E-012见下表；业务ID及金额使用字符串。请求头带Bearer token；服务端按当前账号、最新家庭关系和同意鉴权，不仅信任JWT内旧family_id/child_id。详细校验、分页及JSON示例见修订基线第5节。

错误码PRDHTTP含义
E-001无微信授权401未登录访问写操作（仅可浏览）
E-002档案未补全409需要完整档案的偏好读写操作拒绝并引导家长补全；家长档案GET未建档返回404，已有档案200返回profileStatus
E-003邀请码过期400邀请码 24h 失效
E-004监护人核验失败400非监护人/信息不符
E-005提交结果未知无响应 / 503 / 504网络断开可能无HTTP响应；同键重试或查单，不伪装状态冲突409
E-006虚拟余额不足409扣减时余额<金额
E-007并发扣减冲突409行锁及版本校验版本冲突
E-008通知发送失败200/warn双通道降级，站内保底
E-009越权访问403访问非本家庭数据
E-010家长撤回同意409相应能力已降级
E-011额度超限/预览失效409返回最新额度与版本，须重新显式确认
E-012幂等键参数冲突409同键不同请求摘要，拒绝执行

八、非功能与合规要点

性能 / 安全（引用 PRD 十一）

  • 性能验收提案：骨架P95≤1s、可操作P95≤2s、API P95≤300ms；每日已提交事件中5秒内站内可查询≥99%，非送达率。100并发/1000家庭及设备/网络/时长条件统一采用修订基线第6节。
  • 安全：JWT分权；虚拟钱包扣减采用事务、行锁及版本校验；儿童数据加密存储、最小化采集；未登录401、已登录越权403、不可见资源404；记录脱敏安全日志，后台关键操作留审计。
  • 不采集：V0.0.1 不采集儿童真实位置/人脸；OCR/位置待 P2+ 且需同意。

无障碍 / 未成年人模式（引用交互 8 / 9）

  • WCAG 2.2 AA：对比度 ≥4.5:1、组件 ≥3:1；状态配图标+文字不纯靠颜色；触控 ≥44×44px；动效仅 transform/opacity 且尊重"减少动态效果"。
  • 儿童保护策略提案：时长/夜间设置待产品及合规确认；22:00–08:00仅候选儿童侧规则，不锁家长管理和权利请求，不作统一法定义务断言。
  • 儿童情绪保护（R-03）：仅见状态，不现"被拦截/拒绝"负面词；驳回原因家长温和说明。

合规审计基线（引用全局第八章）

  • 同意留痕：监护人同意书独立勾选、不与登录合并；通过写 usr_consent_log（VERIFIED + 时间戳）；撤回即时降级 + 留痕（E-010）。
  • 虚拟消费合规：仅虚拟记账 + 额度护栏，儿童端无真实支付；超额异步复核非实时拦截。
  • 监护人核验：自报仅SELF_ATTESTED；身份与监护关系证据独立，Q-01未批准不开放真实儿童数据。
  • 虚拟兑换：奖励兑换中心 P2 仅限虚拟权益，规避经营资质风险。
  • 审计：同意/记账/审批/越权须写入sys_audit_log（R-12），并验证覆盖、脱敏与保留策略；审计记录不能替代适用法规和处理依据审核。

10.1 实现层补充假设

  • A-邀请码：6 位大写字母数字，24h 有效；过期需家长重新生成（E-003）。
  • A-撤回窗口：仅PENDING可撤回为CANCELLED；COMPLETED不能拒绝、改写或撤回；异常经对账与受审计的人工处理。
  • A-超额防刷：阈值、窗口、去重与429重试提示待产品/安全批准并配置；发布前完成边界测试。不能把金额幂等代替频控，也不宣称未定义次数上限已可实现。
  • A-订阅模板：上线前须在微信公众平台提前申请订阅消息模板（审批提醒/确认完成）。
  • A-隐私请求：首版人工办理导出/删除，必须有受理人员、身份复核、处理进度、鉴权下载与清理验收（F-012/US-9）；全自动办理后置，不能只交付空入口。
  • A-多孩：全局已裁定 V0.0.1 单孩优先；若支持多孩，家长端/看板顶部"孩子选择器"，数据按 child_id 隔离（R-14）。
  • A-虚拟消耗额符号：全接口/界面金额标注"虚拟"，¥ 非真实货币（R-15）。
