A. 开篇与目标

目标：本计划将详细分析设计文档（16 张表 DDL 就绪、8 组 REST 接口、5 张核心流程图）转换为研发可执行的 4 个 Sprint，明确每个阶段的目标、功能清单、数据表、接口组、交付物与进出准则（DoD），并给出端到端里程碑、依赖图、测试策略、风险回滚与交付矩阵。

范围：严格 = V0.0.1 = P0 地基 + P1 点餐 MVP，覆盖 F-001~F-023（共 23 个 F）；不含 P2–P4（真实支付、课表作业、AI、成长树、多孩 UI 等仅占位或置灰）。

衔接：本计划不新增架构决策，全部沿用《全局规划设计文档》与《详细分析设计文档》的裁定与口径；术语、视觉风格、功能编号、表名、接口路径与上文一致，便于回溯。

A.1 已裁定约束（必须沿用，不得推翻）

数据 / 状态机

  • 逻辑删除：delete_at BIGINT DEFAULT 0（非布尔 deleted）；业务唯一键设计成 UNIQUE(biz_col, delete_at)，实现"删了还能重建"。
  • 扣减时机：统一在家长同意后（APPROVED→COMPLETED）发生；提交只做预校验 + 置 PENDING，提交不扣减。
  • 钱包并发：life_wallet.version 乐观锁 + 事务，防并发超扣（E-007）。

技术 / 合规

  • 技术栈：Java 21 LTS + Spring Boot 4.1.1 + MyBatis-Plus + MySQL 8.0 + Redis + JWT；三角色（CHILD/PARENT/ADMIN）。
  • 分层 + 域前缀：接入/网关鉴权/业务+中台/数据/基础设施；表前缀 usr_/life_/sys_（edu_ 仅占位）。
  • 零真实支付：全为虚拟消耗额（¥ 非真实货币）；短信仅兜底后置（Q-02）。

C. 端到端核心链路里程碑

沿"儿童确认今日菜单 → 家长额度护栏 → 虚拟记账 → 正向反馈"最小闭环（G1）拆解为 7 个核心里程碑，每个里程碑给出进入/退出口径与归属 Sprint。里程碑是 Sprint 内的关键验收节点，也是跨 Sprint 的衔接闸门。

M1
地基贯通（Sprint 1）— 微信登录→角色→档案→家庭→绑定→监护人同意全链路跑通。退出：AUTH/FAMILY/COMPLIANCE 关键路径集成测试通过，越权/E-009 覆盖。
M2
钱包就绪（Sprint 2）— 虚拟钱包+额度规则+流水+站内通知中心可用。退出：余额初始0、额度默认/可改、流水快照、红点逻辑正确。
M3
菜单上线（Sprint 3 前半）— 后台菜品库+当日菜单配置，儿童端可按校/餐段浏览（忌口过敏灰显）。退出：MENU 接口与 life_menu_daily 配置联调通过。
M4
确认闭环（Sprint 3 后半）— 儿童确认→家长审批→同意后扣减→状态追踪端到端。退出：G1 闭环成功率 ≥ 95%，扣减时机正确(E-006/E-007)，超额显式放行。
M5
三通道通知（Sprint 4 前半）— 订阅+站内+短信兜底三通道与降级。退出：触达 ≥ 99%(站内保底)，订阅授权引导就位，短信仅兜底(Q-02)。
M6
合规与安全加固（Sprint 4 中）— 未成年人模式/WCAG/情绪保护/审计全量。退出：非功能与合规清单达标，sys_audit_log 覆盖关键操作。
M7
灰度上线验收（Sprint 4 末）— 白名单灰度放量→全量，验收清单全通过，版本闸门 Q-06 收口。退出：无阻断问题，可正式上线。
里程碑总览：共 4 个 Sprint、7 个核心里程碑（M1–M7）。其中 M1–M2 为地基与钱包底座，M3–M4 为点餐核心闭环（G1），M5–M7 为通知/合规/上线收尾。

E. 测试策略

单元测试

  • 额度校验逻辑（单笔/日/周，默认 30/30/150，Q-04）。
  • F-019 状态机流转（DRAFT/PENDING/APPROVED/REJECTED/COMPLETED）边界。
  • 逻辑删除 delete_at 唯一键重建语义（删后可再建）。
  • JWT 三角色分权与 token 失效/刷新。

集成测试

  • 全链路：登录→家庭→同意→菜单→确认→审批→扣减→通知（覆盖 M1–M4）。
  • 通知三通道降级：订阅未授权→站内保底；关键安全→短信兜底(Q-02)。
  • 数据隔离：跨家庭访问返回 403(E-009)。
  • 同意撤回即时降级(E-010)与留痕。

E.1 并发安全用例：虚拟钱包扣减（乐观锁 + 事务）

用例场景预期对应错误码
CONC-01 乐观锁串行同一儿童两笔家长审批并发触发扣减事务 + version 条件更新，串行化成功，余额绝不超扣—
CONC-02 版本冲突重试两笔扣减同时读到同一 version，后者更新 0 行后者返回并发冲突，提示重试（不超扣）E-007
CONC-03 余额不足扣减金额 > 余额标记异常、不扣减、通知家长E-006
CONC-04 提交不扣减儿童提交确认单仅 PENDING + 预校验，余额不变（扣减在同意后）—
// 伪代码：扣减核心（事务内）
begin transaction
  wallet = selectForUpdate(childId)   // 取 balance 与 version=v0
  if wallet.balance >= amount:
     rows = update wallet
            set balance = balance - amount,
                version = version + 1
            where id = wallet.id and version = v0
     if rows == 0: throw E007_CONFLICT   // 并发版本冲突
     insert life_allowance_log(DEDUCT, snapshot)
     update confirm.status = COMPLETED
     commit
  else:
     rollback; notifyParent(E006_INSUFFICIENT)

  • 阶段划分：内部灰度（运营+种子家庭）→ 小范围家长 → 全量；按家庭/学校白名单放量。
  • 回滚策略：前后端独立可回滚；数据库变更走可逆 DDL（新增列/表优先，避免破坏式变更）；配置开关降级（如短信通道、未成年人模式阈值）。
  • Q-06 版本闸门：发布前验收 Java 21 + Spring Boot 4.1.1 GA 与 MyBatis-Plus 兼容；不兼容则锁稳定版（R-10），不阻塞业务发布。
  • 监控：确认转化率、通知触达率、钱包扣减异常率（E-006/E-007）为灰度核心指标，超阈值自动触发回滚。
