> 配套：设计稿 `docs/P0_每日想吃数据模型落地设计.md`（已确认「按推荐来」）。本文件是编码前的精确改动清单与回滚点。

## 一、改了什么 / 为什么

把「想吃」从 `ChildProfile.favoriteDishIds`（扁平终身收藏）迁移到新表 `usr_child_want_eat`，绑定 `(childId, menuDate, mealType)`，实现真正的「每日想吃」。与保留的「确认单」（`life_menu_confirm`）并存。

## 六、实现偏差与最终定稿（编码后回填）

下列 4 处在编码/联调阶段相对上文清单发生了调整，最终以本节为准。

### 1. `dishType` 由「可选」改为「必填」（重要）
- 原因：测试暴露 PRESET/FAMILY **同号碰撞**场景——当 `PRESET:1` 与 `FAMILY:1` 同时出现在一张菜单里，"按 id 反查菜单取第一个类型"必然歧义，会把 FAMILY 菜品错存为 PRESET。
- 定稿：`resolveDishType(req)` 只做**校验**，不再猜测；`dishType` 缺失或非 `PRESET`/`FAMILY` → `E400`。服务端再校验 `(dishType, dishId)` 必须命中菜单 `dishIds` 中的某个 typed ref，否则 `E404`（既消歧义，又顺带完成菜品越权校验）。
- 兼容性：小程序 `pages/menu/index.js` 的 `favorite()` **本就已传** `dishType: dish.sourceType`（daily 响应逐菜返回 `sourceType`），故无需改造。

### 2. 唯一键增补 `delete_at`
- 原设计：`uk_child_date_meal_dish (child_id, menu_date, meal_type, dish_type, dish_id)`。
- 定稿：`(... , dish_id, delete_at)`。
- 原因：软删除实现下，取消（`delete_at` 置非 0）后旧行仍占用唯一键，导致「取消→重新想吃」插入 0 行 → `requireInserted` 抛 `E007_CONCURRENCY_CONFLICT`（409）。加入 `delete_at` 后唯一性仅约束**未删除行**，语义正确。

### 3. `ChildWantEatMapper` 保持极简
- 清单第 3 条提到的 `selectByChildDateMeal`/`deleteByUniqueKey` **未实现**——统一用 `BaseMapper` + `QueryWrapper`（`wantEatKey(...)` 辅助方法）表达，避免重复的 SQL 面；`delete` 走 `deleteById`（软删）。

### 4. 测试落地位置调整
- 原计划的独立 `WantEatIT.java` **未单独建文件**，相关用例并入 `CatalogFlowIT`（复用其 `FamilyContext`/`favorite`/`childWantEat`/`familyDish` 等 helper，减少 Testcontainers 重复启动）。新增/改写用例：
  - `dailyWantEatIsScopedToChildAndMealAndExposesParentView`（幂等、CHILD 专属、他人 childId→400、取消删行、缺字段→400、下架菜品→404、家长可查）
  - `wantEatIsIsolatedByDateAndMeal`（A 午餐 true / A 晚餐 false / B 日 false / 取消→false）
  - `wantEatQueryIsScopedToFamilyForParent`（家长可见；别家 parent/child → 403）
  - `presetAndFamilyDishWithSameIdDoNotCollide`（typed refs 混排：落库 2 行、daily 两道均高亮）
  - `markingAgainstNonExistentMenuFails`（menuId=9999999 → 404）
- `PrivacyWorkflowIT` 原本即用 typed `"PRESET:..."` 字符串，行为一致，**未改动**。

### 5. 测试基础设施补丁（非业务，但为跑通用例所必需）
- `src/main/resources/application-test.yml` 的 `schema-locations` **补上 `classpath:v005_child_want_eat.sql`**。此前漏列，导致 Testcontainers 里没有该表 → 全部相关用例 500（`Table 'test.usr_child_want_eat' doesn't exist`）。`sql/` 目录已被 `pom.xml` 配为 test-resource，故文件本身在 classpath 上，只需登记进列表。

### 6. 测试断言写法注意（Jayway JsonPath 陷阱）
- `$.data.dishes.length()` 在 `dishes` 元素为对象时会被**分发**到每个对象（返回每个对象的字段数，如 `[17,17]`），而非数组长度。`$.data.wantEat.length()`（元素为简单对象/数组）则正常。故撞号用例改为**按索引断言** `dishes[0]`/`dishes[1]`（菜单返回顺序确定：PRESET 在前、FAMILY 在后），避免歧义。
