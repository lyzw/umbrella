二、导航架构问题（核心，P0）

底部导航 app-nav 仅被 home/index.wxml 引用（已在全仓 grep 验证，仅 home 的 json/wxml 出现）。这意味着：进入 menu / confirmation / wallet / family / profile / notices / privacy 任一子页后，底部 Tab 栏消失，用户只能依赖系统返回键，没有持久导航锚点。

现状（问题）

首页 Home（唯一带 Tab 栏）
├ 点餐/任务/学习/成长/我 → 页内切换 active
├ 审批 tab → navigateTo confirmation
├ 看板 tab → navigateTo wallet
子页面（无 Tab 栏，无返回首页入口）

建议方案 A（推荐）

Tab 栏全局常驻（各主页面底部）
tab 点击 → 已在该页则 navigateBack 到 home 并切 active；否则 navigateTo
子页面同样挂载 Tab 栏，active 同步当前页
统一"切换型"与"跳转型"为同一导航契约

附带语义问题（同属 P0/P1）

  • 儿童 "我" Tab 图标为 ●：纯圆点无语义，应改为账户/人物图标（如 👤 或 "我"）。
  • 家长 Tab 用 ⌂ ▥ ⚙ 等生僻字形：跨字体/机型渲染不稳定，建议改用通用图标或纯文字。
  • 家长 "看板" Tab 实际打开 wallet 页（标题"虚拟零花钱"）：标签与内容不符，建议将 Tab 文案改为"钱包"，或该页升级为真正的看板后再用"看板"。
  • 家长 4 个 Tab 中 2 个跳转、2 个页内切换：同一栏内导航行为不一致，用户难以建立心智模型。

三、主题一致性问题（P1）

家长视图通过 .parent 类把 --primary 由蓝换绿，按钮、激活态、强调色均已贯通。但以下全局类写死了蓝色字面量，家长模式下仍显示蓝色，破坏双主题一致性：

位置（app.wxss / 引用）现状应为
.badgebackground:#eff6ff; color:#1d4ed8;var(--primary-soft) / var(--primary)
.favorite-button（menu）#eff6ff / #1d4ed8变量化
.row-badge（home 未读）#eff6ff / #1d4ed8变量化
.empty-state-icon（menu）background:#eff6ffvar(--primary-soft)
/* app.wxss 修复示例 */
.badge{ background: var(--primary-soft); color: var(--primary); }
.favorite-button{ background: var(--primary-soft); color: var(--primary); }
.row-badge{ background: var(--primary-soft); color: var(--primary); }

六、修复优先级路线图

阶段 1（P0，必做）：重构导航——决定采用"方案 A 全局 Tab 栏"或"首页单一宿主 + 子页显式返回"。同步修复儿童"我"图标、家长 Tab 文案与字形、切换/跳转行为一致性。
阶段 2（P1）：贯通家长主题（4 处写死蓝色变量化）；通知红徽标降色至 #c62828；补子页返回入口（若阶段 1 选首页宿主方案）。
阶段 3（P2）：角色选择等权、checkbox 放大、通知未读强调、确认单字段统一、hero 窄屏兼容。建议随常规迭代处理。

七、设计验收（Design QA）清单

  • 320 / 375 / 430px 三档下布局无溢出、无文字截断；
  • 家长/儿童双主题主色、徽标、激活态完全一致；
  • 正文/小字对比度 ≥ 4.5:1，大字号 ≥ 3:1（WCAG AA）；
  • 所有可点击目标 ≥ 44×44px，间距 ≥ 8px；
  • 空/错/加载/禁用四态在每页均可触发并样式正确；
  • 导航栏在任意主页面常驻且 active 高亮正确。
